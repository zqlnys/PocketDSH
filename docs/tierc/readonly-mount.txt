Why this proves the wrapper works:

- iSH's realfs stores MS_READONLY_ in mount->flags but never reads it, so a
  read-only mount that only set the flag would still accept writes. That is
  why the wrapper exists.
- Both write attempts failed with "Read-only file system": the EROFS the
  wrapper returns travels through the emulated kernel into the guest shell.
- Reads still work: `ls /workspace` lists README.md, so the mount is not
  simply broken.
- The host confirms no file was created, so this is not just a shell-level
  error message.
- `write-exit:1` is the exit status the guest observed.

Note: commands 4 and 5 belong to the read-write probe sequence, which this
run inherits; they fail here by design. A later revision switches the command
set by mount mode so the read-only screenshot only shows relevant checks.
