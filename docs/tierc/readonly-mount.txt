Why this proves the wrapper works:

- iSH's realfs stores MS_READONLY_ in mount->flags but never reads it, so a
  mount that only set the flag would still accept writes. The wrapper exists
  precisely because the flag alone is cosmetic.
- The write failed with "Read-only file system": the EROFS the wrapper returns
  travels through the emulated kernel into the guest shell.
- Reads still work: `ls /workspace` lists README.md, so the mount is not simply
  broken.
- The host confirms no file was created, so this is not just a shell message.
- `write-exit:1` is the exit status the guest observed.
- The session survives the rejected write (session active: yes), so a failed
  write does not poison the shell.
