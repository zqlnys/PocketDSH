What each line proves:

- Six commands run in ONE session; the previous bridge started a whole
  emulated kernel per command.
- `uname -m` is an external command. Before the exit_hook fix it took the
  session down with it, and the next line reported `shell error -32`.
  `alive-after-external` proves the session survived a forked child.
- `read v < /workspace/...` is a shell builtin, so the mount is readable
  without spawning anything: got:tierc-write-ok.
- `ls /workspace` lists README.md — the real project file through realfs,
  not an empty mount point.
- `still running: yes` — the session is reusable, not single-shot.
- Host readback still matches, so the mount remains a two-way share.

Timing:

  Every command reports +0.1s. The 1-3s per-command cost seen in earlier
  builds was entirely the per-command kernel startup (xX_main_Xx + mounts),
  not the command itself. Keeping one shell removes it.

Known limitation:

  Terminal sessions are serialized. A second pocket_shell_start() returns
  "another shell session is active" until the first is stopped.
